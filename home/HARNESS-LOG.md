## 4. 스크린샷 비용 근거 정정 (2026-07-28, 커밋 6100c4a)

**문제**: CLAUDE.md가 base64 **글자수를 토큰수로 환산**해 스크린샷 장당 비용을 50~100배 부풀려 적고 있었다.

**정정**: 이미지는 픽셀 기준((w×h)/750)으로 토큰이 매겨진다. 실측에서 base64 5,096k자 이미지가 컨텍스트를 **+1k 토큰만** 늘렸다.

**결론**: 규칙(서브에이전트 위임)은 **유지**하되 "누적은 실재하나 비용을 이유로 다른 규율에 앞세우지는 않는다"로 격을 낮췄다.
**교훈**: 근거 수치가 틀려도 규칙이 맞을 수 있다. 근거를 고치고 규칙은 따로 재평가한다.
(이 함정은 메모리 `feedback_token_audit_pitfalls.md`에도 있다.)

## 14. 세션을 닫아도 워크트리·브랜치가 남음 (2026-08-05)

**문제**: `/close-session`은 idle 마커만 찍고 끝나서, 세션이 만든 워크트리와 브랜치가 계속 쌓인다. pholex 실측에서 워크트리 7개(.claude/·.codex/·orca/ 혼재)가 붙어 있었다.

**함정**: 이 명령은 `idle-return-guard.sh:24`가 `decision:"block"`으로 끊어 **모델이 아예 안 뜬다**(#1 설계, 토큰 0이 목적). `skills/close-session/SKILL.md`는 훅이 안 걸렸을 때의 fallback일 뿐이다 — 정리 로직을 스킬에만 넣으면 정상 경로에서는 **영영 실행되지 않는다**.

**수단**: `close-session-cleanup.sh` 신설(bash 3.2). 훅과 스킬이 **같은 스크립트를 호출**해 규칙을 한 곳에 둔다. 훅은 리포트를 block reason에 이어붙여 모델 없이 사용자에게 보여준다 — 토큰 0 유지.
- 워크트리 제거 조건 3개 **전부** 만족일 때만: clean + `origin/<default>`의 조상 + unlocked. 본체와 현재 CWD 워크트리는 무조건 제외. `--force`·`stash` 안 쓴다.
- 브랜치는 머지된 것 + upstream `[gone]`인 것을 `git branch -d`로만 삭제. **`-D`를 안 쓰므로 커밋 유실이 구조적으로 불가능**하다(squash 머지된 gone 브랜치는 `-d`가 거부 → 삭제 명령만 안내하고 남긴다).
- `git worktree remove`가 미추적 파일에도 거부하므로 리포트에 추적/미추적을 나눠 표기한다("미추적만 7건"이면 사용자가 빌드 산출물인지 바로 판단).
- `CLOSE_SESSION_DRY_RUN=1` / `CLOSE_SESSION_NO_FETCH=1` — 파괴적 스크립트라 검증 수단을 내장했다. 수정 후 반드시 dry-run으로 판정부터 확인할 것.

**규율 1(소프트 개입 우선)의 변형**: 차단이 아니라 **보존**이 기본값이다. 애매하면 지우지 않고 보고만 한다 — 오탐의 대가가 여기서는 "정리가 덜 됨"(무해)이 아니라 "남의 세션 작업 삭제"(복구 불가)라서, #7·#10과 달리 재시도 통과 경로를 두지 않았다.

**재측정**: 다음 `/close-session` 실행 시 리포트의 제거/유지 건수. 유지 사유가 "미추적만"으로 계속 쌓이면 그때 정책을 다시 본다.

## 16. 핸드오프가 없는 스킬을 계속 권함 + model·effort 레버 미사용 (2026-08-07)

**문제 A (드리프트)**: `#12`에서 superpowers를 끄고 로컬 `writing-plans`에서 SDD 문구를 지웠는데, **핸드오프 문장은 `plan-saved-session-boundary.sh`에 하드코딩돼 있었다**(76·82·90행). 그래서 플랜을 저장할 때마다 없는 스킬을 계속 권했고, 사용자가 08-06 이후 킥오프 5회 전부에 `subagent-driven-development 스킬 없이`를 손으로 붙여 지웠다. **스킬 파일과 훅이 같은 문장을 두 곳에서 소유한 게 원인이다.**

**문제 B (미사용 레버)**: 구현 세션의 `model`·`effort`를 한 번도 명시하지 않았다. `claude --effort` / `/effort`(→ `settings.json`의 `effortLevel`) / 에이전트 frontmatter `effort:` 3개 surface가 전부 있는데, 실제로 쓴 건 `Explore.md`·`screenshot-verifier.md`의 `effort: low`뿐이었다.

**조사 근거**:
- [The Subagent Tax](https://systima.ai/blog/subagent-tax) Opus 5 매칭 실측 — 순차 295k/4m15s, 2에이전트 762k/**8m**, 5에이전트 945k/4m45s. **한 번도 순차보다 빠르지 않았다.** 그리고 비용을 움직이는 건 에이전트 수가 아니라 **에이전트당 턴 수**(5개가 2개보다 토큰을 덜 쓴 역전이 Opus·Fable 양쪽에서 발생).
- [Effort 문서](https://platform.claude.com/docs/en/build-with-claude/effort) — 낮은 effort는 툴 호출을 병합·감소시킨다. 즉 **턴 수를 직접 제어하는 게 effort다.** 또한 effort 값이 렌더된 프롬프트에 들어가므로 **세션 중 변경은 캐시 프리픽스를 무효화한다.**
- [Prompting Claude Opus 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5) — *"legacy harness scaffolding that adds separate verification steps"* 는 over-verification을 유발하니 제거하라, *"Do not use subagents to verify or double-check your own work."* → **SDD의 2단계 리뷰 게이트가 여기 걸린다**(#9가 배치로 줄인 것과 같은 방향, 더 강하게).
- [Prompting Claude Sonnet 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5) — Sonnet 5 @ medium ≈ Sonnet 4.6 @ high. low/medium에서는 *"scopes its work to what was asked rather than going above and beyond"* → 완결적 `task-N.md` 실행에서는 이게 금도금 방지로 작동한다.

**수단**:
- 훅 4개에서 SDD 스킬명 제거. `sdd-kickoff-guard.sh`는 **트리거를 스킬명 → 구현 의도 정규식으로 교체**했다 — 안 고쳤으면 새 킥오프 문구에 가드가 안 붙어 "플랜 통째로 Read 금지"가 조용히 죽는다(아래 표 갱신됨).
- `~/.claude/plan-exec-modes.md` 신설 — 모드 ①속도(xhigh+sonnet, 트랙 단위 worktree 병렬) / ②절약(medium+sonnet, 서브에이전트 0) / ③최고품질(xhigh+opus+별도 리뷰어). 공통 규칙에 "구현자에게 검증 지시 금지", "태스크 단위 팬아웃 금지", "effort는 세션 시작 시 고정".

## 18. 크로스세션 메시징이 기본 ON (2026-08-10)

**발단**: 사용자가 "세션끼리 대화하는 기능이 기본값으로 추가된 것 같은데 워크플로우 개선에 쓸 수 있나"를
물었다. 확인해보니 **team mode가 기본으로 병합된 게 아니라 별개 기능**이었다 — 에이전트 팀은 여전히
`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` opt-in이고 `ListAgents`에 뜨지도 않는다. 새로 켜진 건
독립 세션끼리 평문을 주고받는 별도 채널(2.1.224+, **마스터 스위치 없이 기본 ON**)이다.
이 머신은 `remoteControlAtStartup: true`라 모든 세션이 주소를 갖고, `crossSessionInbound` 미설정이라
**최대 노출 상태**였다. `ListAgents`에 339행이 떴다(Remote Control 333 + interactive 6).

**문제**: 문서 확인 결과 **idle 세션은 메시지를 받으면 새 턴을 시작한다 — 사람이 없어도.**
비용은 "counts toward usage like a prompt you type", 즉 **그 세션의 현재 컨텍스트 크기**로 한 턴이다.
300k 세션이 TTL(1h) 지난 뒤 깨면 프리픽스 전체 재캐싱이고, 이건 R6이 존재하는 이유 그 자체다.
게다가 R13 마커는 세션 1회라 이미 소진돼 있으면 다시 안 걸린다.
**이 하네스의 개입은 전부 "턴은 사람이 연다"를 암묵 전제로 깔고 있었다** — R6은 사람이 돌아올 때
가드하고(UserPromptSubmit), R13은 턴이 끝날 때 깨운다(Stop). 피어가 턴을 열면 그 전제가 세션 밖에서
무너진다. 그래서 규칙(R15)을 만드는 대신 **채널을 닫는** 쪽을 골랐다 — 규율 2의 적용이다.

**수단**: `~/.claude/settings.json`에 `crossSessionInbound: "refuse"`.
`bootstrap.sh` ③의 jq 병합에도 넣었다 — 안 넣으면 이 결정이 **이 머신에만** 살아 있고 새 머신에서
조용히 안 걸린다(statusLine과 같이 머신 고유 키가 아니라 하네스 정책이라 무조건 덮는다).

**기각** (상세는 workflow-spec §7-A):
- **`hold`** — 기술적으로는 규율 1에 더 맞다(사람 있으면 승인, 없으면 5분 뒤 드롭, 같은 머신 발신자는
  결과를 통보받음). 그런데 이 하네스에 피어를 쓰는 경로가 **0개**라, 얻는 건 "언젠가의 편의"인데
  대가는 매 수신마다의 다이얼로그다. **쓸 경로가 생기면 refuse보다 hold가 먼저다.**
- **구현 스킬에 "세션 간 대화 툴 금지" 문구** — 사용자가 제안했고, "무시돼도 추가비용만 생기지
  결과물엔 무해하다"가 근거였다. outbound에는 맞는 말이지만 **막아야 할 축은 inbound**고, 인바운드 턴은
  모델을 거치지 않으므로 그 문장이 읽히기 전에 이미 청구된다. 게다가 구현 스킬은 구현 세션만 로드해서
  정작 발신할 법한 워크트리·Remote Control 세션은 그 문장을 안 읽는다(§6-6 반쪽 소유권).
  `SendMessage`는 자동 발화도 없어 관측된 실패가 0건이다.

**대가 (반드시 기억할 것)**: **`refuse`는 발신자에게 아무 통지도 안 간다** —
"A message refused on arrival produces no sender-side notice." 다른 세션에서 이 머신으로 보냈는데
답이 없으면 상대가 바쁜 게 아니라 이 설정이 버린 것이다. workflow-spec §8에 같은 경고를 박아뒀다.

**남긴 것**: 발신(outbound)은 막지 않았다. 값이 있는 방향은 그쪽뿐이고
(레포가 달라 한 세션에 못 합치는 질의, 저쪽 세션만 아는 기각 이력), 유일하게 구체화된 용처는
**R13 핸드오프 창**이다(→ §8 O12).

**재측정**: 이번 건은 절감이 아니라 노출 차단이라 달러 재측정 대상이 아니다. 대신 세 가지가
미검증으로 남았고 **`refuse`를 푸는 순간 전부 결정에 개입한다**: O10(인바운드 턴이 `UserPromptSubmit`을
태우는지 — `hooks.md` 전문 grep 0건, 안 태우면 훅 3개 우회) · O11(transcript mtime 갱신으로 R6 타이머

대상으로 삼는다 — 이번 판정(다운로드 여부)과 그 판정(가치 있는지)은 다른 질문이다.

## 20. 사용량 하드 컷은 R13이 못 덮는다 (2026-08-10)

**발단**: 플랜 구현 중 세션이 끊기는 일이 반복됐다. 처음엔 R13(300k 자동 핸드오프)이 겨누는 것과
같은 문제로 보였는데, 확인해보니 **컨텍스트 창이 아니라 사용량 하드 컷**이었다. 둘은 커버가 갈린다 —
R13은 Stop 훅이라 **턴이 끝날 때만** 발화하고, 하드 컷은 턴 도중에 온다.

**문제 A (사전 경고가 불가능)**: `statusline/ctx-warn-statusline.sh`는 컨텍스트만 센다.
훅 입력에도 사용량 잔량이 없다. 즉 R13이 쓴 수단(임계에서 깨워 대체 경로를 만들어 준다)을
**여기서는 쓸 수 없다.** 그래서 이 규칙은 조건부가 아니라 무조건 절차다.

**문제 B (핸드오프 문서를 못 찾는다)**: R13은 문서를 `~/.claude/idle-handoffs/<session_id>.md`에
저장한다. 하드 컷당한 세션의 id를 새 세션은 모르므로 **컷 뒤엔 그 문서에 도달할 수 없다.**
회복 진입점이 사전지식 없이 찾히는 곳에 있어야 한다는 요구가 여기서 나왔다.

**수단**: R15 신설. `plan/<name>` 브랜치 + 플랜 문서 첫 커밋 + **draft PR**을 구현 첫 턴에
만들고, 레이어마다 **커밋 → 리뷰 → push**. 마지막 레이어를 push하면 `gh pr ready`로 draft를 벗긴다
(issue #3 — ready~머지 창에서 다른 세션이 "진행 중"으로 오판하는 걸 막는다. 처음엔 `plan-wip`
라벨을 뒀다가, 라벨이 나르던 정보가 전부 draft + `plan/` 접두어에서 파생 가능해 **라벨을 없앴다**).
훅은 **하나도 추가하지 않았다** — 전달 경로가 이미 있다
(모드 파일은 킥오프 훅이 읽게 만든다). 기존 훅 수정 1건: `stale-branch-guard.sh`가 플랜 브랜치에서
문구를 하향한다(면제가 아니라 등급 하향 — 경고·마커·ack 게이트 유지).

**설계 판단 — 하드 컷은 파일을 지우지 않는다.** 워킹 트리는 디스크에 남는다. 처음엔 task 단위 커밋을
생각했는데(손실 상한 = 커밋 간격), 그건 파일이 날아가는 실패를 가정한 것이었다. 실제로 잃는 건
**"어디까지 했는지"라는 기록**이라 커밋의 역할은 보존이 아니라 **라벨링**이고 레이어 해상도로 충분하다.
task 단위는 ②a에서 git 출력이 오케스트레이터 floor에 쌓여 매 요청에 재청구되는 대가까지 있었다.

**대가**: 버리기가 되돌리기로 바뀐다(§3 R15 참조). 이 교환의 판정은 **하드 컷 빈도 vs 방향 오류 빈도**이고
아직 세지 않았다 — §8 O14. 그리고 R13의 유인을 약화시킬 수 있다: 끊겨도 안 아프면 `/clear`를 미룬다.
재측정에서 "핸드오프 문서를 썼는데도 `/clear` 안 함" 비율이 오르면 **원인 후보로 이 규칙을 먼저 보라.**

**재측정**: 아직. O14를 먼저 세야 판정 기준선이 생긴다.

## 21. 정리 규칙이 원본 머신에만 있었다 — 그리고 이름으로 판정하고 있었다 (2026-08-12)

**발단**: "`/close-session`이 안 쓰는 프로세스 정리하는 스텝, 특정 앱은 예외처리 할 수 있어?"
라는 질문 하나로 시작했는데, 답을 찾는 과정에서 결함 4개가 연달아 나왔다.

**문제 A (레포에 없었다)**: `close-session-cleanup.sh`는 `~/.claude/hooks/`에만 있었고
`idle-return-guard.sh`가 그걸 **절대경로로** 부르고 있었다. 훅 12개 중 유일하게
`${CLAUDE_PLUGIN_ROOT}`를 안 쓴 참조다. 즉 정리 규칙 전체가 원본 머신 로컬이었고,
다른 머신에서는 훅이 조용히 아무 일도 안 하고 지나갔다. README는 이걸 "wire 안 된 잔재"로
분류해 두어 **문서가 오히려 발견을 늦췄다** — 실제로는 wire 돼 있었다.

**문제 B (이름으로 판정하고 있었다)**: 앱 종료 대상을 프로세스 **이름** 목록으로 골랐다.
그런데 Playwright가 띄운 Chrome도 프로세스 이름은 그냥 `Google Chrome`이다. 예외 목록을
설계하면서 "일상용 브라우저니까 보존"이라고 `keep|Google Chrome`을 넣었는데, 실측해보니
떠 있던 `Google Chrome` **1894MB가 최상위 프로세스 2개 전부 ms-playwright-mcp 인스턴스**였다.
잡으려던 것을 정확히 살려두는 규칙을 쓴 것이다. **이름은 출처의 대리 변수가 못 된다.**

**문제 C (여러 단어 이름이 통째로 누락)**: `APPS="Google Chrome Chromium ..."`을
`for app in $APPS`로 순회해 `Google`·`Chrome` 두 토큰으로 쪼개졌다. `pgrep -x`가 못 잡으니
여러 단어 이름 앱은 **기능이 생긴 이래 한 번도 종료된 적이 없었다.** 한 단어짜리(Slack·Notion
·KakaoTalk)만 죽고 있었으니, 실제 동작은 "e2e 브라우저는 살려두고 메신저를 끈다"였다.

**문제 D (동기 훅이 무한 대기)**: frontmost 판정용 `osascript`는 Automation 권한이 없는
컨텍스트에서 TCC 프롬프트도 못 띄운 채 블록된다. 이 스크립트는 `UserPromptSubmit`에서
**동기로** 도니 세션이 통째로 멈춘다. 실측 2분+.

**수단**:
- 스크립트·정책 기본값을 `woobin-harness/hooks/`로 옮기고 참조를 `${CLAUDE_PLUGIN_ROOT}`로.
  정책 파일은 3단계 탐색(env → `~/.claude/` → 동봉 기본값). **파일 부재의 기본값이
  보수적인 쪽이 아니라 가장 공격적인 쪽**이라 동봉본이 반드시 있어야 한다.
- 판정을 두 갈래로 분리. **출처로 잡는 것**(자동화 브라우저 서명, compose `working_dir`이
  이 레포 안)은 이름·정책·frontmost와 무관하게 정리한다. **이름으로 잡는 것**(사용자가 켠 GUI 앱)만
  `keep`·`ondemand`·`idle|<일수>|<활동경로>` 정책을 탄다.
- 도커는 `stop`이지 `down`이 아니다. 볼륨을 안 건드리므로 dev/prod DB가 살고 `docker start`로 복구된다.
- `osascript`에 상한(`run_bounded`). 실패하면 앱 절을 **통째로 건너뛴다** — frontmost를 모르는 채
  진행하면 지금 쓰는 앱이 보호를 잃는다.

**대가**: 판정 층위가 둘로 늘어 "왜 안 죽었나"의 답이 한 곳에 없다. `CLOSE_SESSION_DRY_RUN=1`이
보존 사유를 찍는 게 그 대가를 갚는 유일한 수단이라, dry-run을 **디버깅 도구가 아니라 설계의 일부**로
취급해라. 그리고 `idle`의 활동 경로는 손으로 고른다 — Electron 앱은 떠 있기만 해도 `Cache`·`DIPS`가
갱신되므로, 그런 경로를 쓰면 앱이 영원히 "활성"으로 판정돼 예외가 조용히 무력화된다.

**재측정**: 아직. 다음 `/close-session`부터 리포트에 회수량이 찍히므로 그걸 기준선으로 쓴다.

## 규율 (이 이력에서 반복 확인된 것)

1. **소프트 개입 우선** — 차단은 세션 1회 + 재시도 통과. 오탐이 영구 장애가 되면 안 된다(#7, #10, #11 전부 이 형태).
2. **소프트 지시로 못 막는 건 구조를 바꾼다** — "부분만 읽어라"가 안 먹혀서 파일 자체를 쪼갰다(#6).
3. **효과는 다음 audit에서 재측정한다** — 처방만 남기면 재발한다(스킬 `checklist.md`의 해결책 사다리 원칙).
4. **근거 수치와 규칙은 별개로 검증** — 근거가 틀려도 규칙이 맞을 수 있다(#4).
5. **env 전역 override보다 PreToolUse 조건부 주입** — 의도적 예외를 조용히 깨뜨리지 않는다(#8).
6. **이름이 아니라 출처로 판정한다** — 이름이 같아도 출처가 다르면 다른 것이다. 이름으로 고른
   목록은 조용히 반대로 동작할 수 있다(#21: e2e Chrome을 살려두고 메신저를 껐다).
