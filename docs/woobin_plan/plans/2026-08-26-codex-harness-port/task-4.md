### Task 4: grill-me 원장 `근거` 열 + 스펙 파일 형식

두 가지를 고친다. 둘 다 `woobin-harness/skills/grill-me/SKILL.md` 한 파일 안이다.

**(1) 결정 원장 표에 `근거` 열을 추가한다.** 지금 §121이 "사용자가 고른 것이 아니라 기본값으로 확정된 것으로 구분해 적어라"라고 요구하는데, §127-139의 표 템플릿에는 **적을 칸이 없다.** 산문 규칙만 있고 칸이 없으면 안 채워진다. codex가 같은 표에 `Source` 열을 만들어 해결했다.

**(2) 스펙을 파일로 떨굴 때의 형식을 5줄로 정한다.** §143이 "언제 파일로 쓰나"(3개 조건)는 정했지만 "무엇을 쓰나"는 안 정했다. 이게 아픈 지점은 §167의 폴백이다 — 컨텍스트가 200k를 넘어 급히 `/clear`를 건네야 하는 상황이고, 그 파일을 읽는 다음 세션은 이 대화를 한 글자도 못 본다. 급한 순간에 형식이 없으면 즉흥으로 만들고, 빠뜨린 건 아무도 모른다.

**검증기·훅·별도 계약 문서는 만들지 않는다.** 강제 장치를 붙이면 (a) 스펙 형식을 서술하는 소유자가 1개에서 3개로 늘고 그중 판정 주체는 드리프트가 눈에 안 보이며, (b) 게이트를 통과시키려고 미결을 가정 절로 미는 우회로가 열린다. 강제하지 않으면 우회할 것도 없다.

- [ ] **Step 1: 원장 표 템플릿에 `근거` 열을 넣는다**

`SKILL.md`의 `## ④ 결정 원장` 절 안, 코드 펜스로 감싼 템플릿을 찾는다. 현재:

```
## 결정 원장 — <주제>

| # | 결정 | 고른 것 | 기각한 것 — 이유 |
|---|------|---------|------------------|
| 1 |      |         |                  |
```

바꾼 뒤:

```
## 결정 원장 — <주제>

| # | 결정 | 고른 것 | 근거 | 기각한 것 — 이유 |
|---|------|---------|------|------------------|
| 1 |      |         | 사용자 선택 / 추천안 기본값 |  |
```

- [ ] **Step 2: `근거` 열이 무엇인지 한 줄로 설명한다**

같은 절의 "기각한 대안과 **그 이유**가 원장의 핵심이다"로 시작하는 문단 **뒤**에 한 줄을 넣는다:

```
`근거`는 그 줄이 사용자가 고른 것인지 내가 추천안대로 확정한 것인지를 가른다. §"빠져나갈 문"이 요구하는 구분이고, 나중에 결정을 뒤집을 때 **무엇을 재검토해야 하는지**가 여기서 갈린다.
```

- [ ] **Step 3: §143 뒤에 스펙 파일 형식 규칙을 넣는다**

"원장은 대화 안에 산다. 파일로 떨구는 건 세 경우다: …"로 시작하는 문단을 찾는다. **그 문단 바로 뒤**에 새 문단을 추가한다. 위치가 중요하다 — "언제 쓰나" 바로 다음이 "뭘 쓰나"여야 한다.

```
파일로 쓸 때는 형식을 맞춘다. 읽는 쪽이 이 대화를 못 본 세션이기 때문이다. frontmatter에 `slug`·`confirmed_at`을 두고, 본문은 여덟 절이다 — Problem / Goals / Non-goals / Decisions / Acceptance criteria / Rejected alternatives / Provenance / Open questions. 원장 표는 Decisions와 Rejected alternatives 둘로 나뉘어 들어가고, **가정**은 Decisions 안에 기본값으로 표시한다.

**Open questions가 비어 있지 않으면 그건 확정 스펙이 아니다.** 파일로 쓰지 말고 대화에서 마저 물어라. 미결을 남긴 채 넘기면 다음 세션이 그 자리를 자기 판단으로 메우고, 그 판단은 사용자가 승인한 적 없는데 구현 세션에선 승인된 것처럼 보인다.
```
