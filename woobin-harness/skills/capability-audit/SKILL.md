# Capability Audit

사용자의 **agentic AI 활용 역량**을 채점하고 `docs/scores/`에 이력을 남긴다.
비용을 보는 `token-waste-audit`과 다르다 — 이건 **사람의 습관**을 본다. 그 도구를 지표 수집에 재사용한다.

## 라우트 선택

인자로 주기를 받는다. 없으면 물어본다.

| 인자 | 라우트 | 설계 의도 |
|---|---|---|
| `weekly` · `monthly` | **A — 스캐폴드** | 재현성이 목적. 낮은 모델로 돌려도 같은 점수가 나와야 추세가 의미를 갖는다 |
| `quarterly` · `half` | **B — 자유** | 새 프론티어 모델에 구형 스캐폴드를 강제하면 손해. 더 깊이 보라고 푼다 |

기본 창(window): `weekly`=7일, `monthly`=30일, `quarterly`=90일, `half`=180일.

---

## 라우트 A — 주간·월간

### 1. 지표 수집

```bash
python3 "$SKILL_DIR/scripts/collect.py" --days <N> --out /tmp/capability-<날짜>.json
```

`$SKILL_DIR`은 이 SKILL.md가 있는 디렉터리다. 레포는 자동 탐색하며,
못 찾으면 `--repo` 또는 `CLAUDE_HARNESS_REPO`로 준다.

JSON을 읽고 `errors` 배열을 먼저 확인해라. 비어 있지 않으면 그 지표는 `null`이고,
루브릭 규칙 3(= 50점 처리 + `부분 측정` 표시)이 적용된다.

2026-08-26 이전 리포트는 서브에이전트 비용을 메인 lane에 합산했다. 그 이전 점수와
sidechain_cost_ratio를 직접 비교하지 마라 — 분모가 다르다.

### 2. 채점

`rubric-v1.md`(디렉터리 안 최신 `rubric-v*.md`)를 읽고 **그대로** 적용한다.
루브릭의 채점자 규칙 5개를 지켜라 — 특히 **JSON 밖의 숫자를 만들지 않는 것**.

`A7_metacognition.prior_actions_started`는 `null`로 온다. 직전 리포트의 "다음 액션" 목록과
`git log`를 대조해 **당신이 채운다.** 증거 파일 경로를 리포트에 적어라.

### 3. 리포트 작성

`<history_dir>/YYYY-MM-DD-weekly.md` (또는 `-monthly.md`):

```markdown
# 역량 채점 — YYYY-MM-DD (weekly)

| | |
|---|---|
| 라우트 | A (스캐폴드) |
| 루브릭 | v1 |
| 채점 모델 | <모델명> |
| 창 | 최근 N일 |
| 표본 | 세션 N개 · 트랜스크립트 N개 |
| 부분 측정 | 없음 / <지표 목록> |

## 종합 — NN점

(A1×18 + A2×20 + ... ) / 100 = NN.N → NN

## 축별

| 축 | 점수 | 지표값 | 밴드 근거 |
|---|---|---|---|
| A1 컨텍스트·비용 | NN | x1=0.NN, x2=NNk | 0.6×NN + 0.4×NN |
| ... | | | |

## 직전 회차 대비

| 축 | 이전 | 이번 | Δ |
|---|---|---|---|

## 총평

(자유 서술 — 점수는 바꾸지 않는다. 추세와 원인만.)

## 다음 액션

- [ ] ...  ← 다음 회차의 A7 t1이 이 목록을 대조한다. 검증 가능하게 써라
```

### 4. 이력 갱신

`<history_dir>/SCORES.md`의 표에 **한 줄 추가**한다(append-only, 기존 줄 수정 금지).

## 라우트 B — 분기·반기

`route-b.md`를 읽고 **그 문서의 지시를 따른다.** 라우트 A의 절차를 여기에 적용하지 마라.

핵심만: 산출물 3개(**① 루브릭 개선안 ② 채점 ③ 다음에 배울 것**)이고, ①이 가장 중요하다.
`collect.py --days <N>`은 참고용으로 돌리되 그 숫자에 갇히지 말고 원본 트랜스크립트를 직접 읽어라.

리포트는 `<history_dir>/YYYY-MM-DD-quarterly.md`, `SCORES.md`에 한 줄 추가.
루브릭 개선안이 채택되면 `rubric-v2.md`를 **새로 만들고** v1은 남긴다 — 과거 점수의 근거이기 때문이다.

---

## 이력 위치

우선순위대로 해결한다:

1. `$CAPABILITY_AUDIT_HISTORY_DIR`
2. `<claude-harness 레포>/docs/scores/` ← 기본
3. `~/.claude/capability-scores/` (레포를 못 찾을 때)

`collect.py`가 낸 JSON의 `history_dir` 값을 그대로 쓴다. 직접 추론하지 마라.

## 규약

- **루브릭 버전이 다른 점수를 비교하지 마라.** 비교하려면 옛 데이터로 새 루브릭을 재적용해야 한다
- **점수를 후하게 주지 마라.** 사용자가 냉정한 평가를 명시적으로 요청했다.
  잘한 축은 높게 주되, 근거 없이 올리지 않는다
- **`docs/workflow-spec.md` §8·§9에 이미 자백된 것을 발견으로 보고하지 마라**
- **리포트를 쓴 뒤 채팅에는 종합 점수·축별 표·다음 액션만 요약한다.** 전문을 다시 붙이지 않는다
