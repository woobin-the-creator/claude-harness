# Direction

## Load this module when

Load only for greenfield product work, a redesign, or a change where the intended product direction is materially ambiguous or expensive to reverse.

Use it to discover the actual direction before selecting palette, density, motion, illustration, or layout signatures. Ask about 실제 사용자 and the primary task verbs they perform.

## Do not load this module when

Skip for established-system incremental changes, bug fixes, review-only work with an adopted direction, and render-invariant logic changes.

Do not use this module to override local design authorities or to re-open direction because a small component feels generic.

## Inputs to inspect before asking

Inspect product copy, route names, domain entities, current components, screenshots if available, and any existing `DESIGN.md`. Identify what is already decided and what is merely observed.

Collect:

- actual user roles and primary task verbs;
- intended feeling and operational risk;
- at least five domain concepts;
- at least five domain-natural color or material associations as exploration, not mandatory final tokens;
- three defaults to avoid because they would make this product feel interchangeable.

## Decisions that require the user

The user must choose before a candidate direction becomes adopted. Ask before locking a signature, a focal point, a high-risk tone, or any direction that would constrain broad future UI.

External interface guidance arrives as constants — a fixed palette, a named font, a 60/30/10 ratio, a single-accent rule. Those numbers were derived from other products. Take the reasoning and derive the value here, from this product's content, density, and task. `principles.md` covers the same point for the usability laws.

## Direction brief

Write a compact brief:

- user and task verbs;
- feeling and operational risk;
- domain vocabulary and material associations;
- one concrete signature;
- one focal point;
- defaults to avoid;
- open questions.

Use “signature” for a recognizable repeated design move, and “focal point” for the first place attention should land.

## Candidate comparison

Offer two or three candidates only when ambiguity is material or the choice is expensive to reverse. Compare them by task fit, emotional fit, risk, implementation cost, and reversibility.

Candidates are `candidate`, not `adopted`, until the user selects one.

## Exit criteria

Exit when the direction brief names the user, task verbs, feeling, risk, signature, focal point, and avoided defaults, or when the user decides that no durable direction is needed for this task.
