# design-variants-to-pr

UI 작업 하나를 **여러 시안으로 병렬 제작 → 한 URL에서 토글 비교 → 사용자가 선택 → 완성 → PR → merge**까지
한 흐름으로 끌고 간다.

이 스킬은 **오케스트레이터**다. 메인 루프는 결정·전달·합치기만 하고, **읽기·쓰기·확인은 전부 위임**한다:
- **병렬 제작**: 시안마다 독립 에이전트 + worktree/브랜치 분리.
- **화면 판정**: `screenshot-verifier` 에이전트. 이미지도 브라우저 루프도 메인에 들이지 않는다.
- **최종 데모 녹화(선택된 시안 1개만)**: `pr-demo-video` (`~/.claude/skills/pr-demo-video/SKILL.md`).

> **선행**: 프런트 작업이므로 `docs/frontend.md`(또는 그 레포의 프런트 규약 문서)를 먼저 읽는다.
> "기존 디자인에 어울리게"가 핵심 요구라, 손대는 컴포넌트의 현재 스타일을 먼저 파악해야 시안이 겉돌지 않는다.

---

## 이 워크플로우의 비용은 전부 "메인 컨텍스트 크기"다

실측 2건(Pholex, 2026-07~08)이 같은 얘기를 한다.

| | 위임한 실행 (6a09249c) | 위임 안 한 실행 (94aff112) |
|---|---|---|
| 메인 루프 | $13.19 / 104 req | **$40.56 / 274 req** |
| 메인 peak 컨텍스트 | 225k | **352k** |
| 서브에이전트 | 20개 | **0개** |
| 메인 tool | Agent 10, Bash 15 | Edit 32, Write 18, Bash 43, playwright 41 |

94aff112를 10% 구간으로 쪼개면 **어느 한 단계가 비싼 게 아니다** — 컨텍스트가 87k→310k로 단조 증가했고
구간 비용이 그 곡선을 그대로 따라갔다. 즉 국소 최적화가 아니라 **한 컨텍스트가 전 공정을 안고 가는 구조**가 원인이다.

그래서 이 스킬의 규율은 두 축이다: **(A) 단계 사이에서 세션을 끊는다**(§0), **(B) 끊긴 구간 안에서도 손발은 위임한다**(§2·§3·§6).
위임만 하고 안 끊으면 잘 된 실행조차 57k→225k로 끝난다 — 후반 절반을 60k에서 돌렸다면 두 실행에서 각각 27%·32%가 절약됐다.

## ⚠️ 비교 단계에서 GIF를 찍지 마라

**시안 비교는 라이브 프리뷰로 한다. 녹화는 선택이 끝난 뒤 최종 1개에만.**

2026-07-30 실측(#192, 시안 3개): 시안 제작 $21.85 중 **녹화·프레임 검증이 $12.74(58%)**. 시안 하나는
녹화에서만 $4.63 쓰고 산출물 0으로 실패했다(전환 320ms가 캡처 10fps와 안 맞아 재녹화 반복).
녹화가 비싼 이유는 프레임 확인이 이미지를 요구하고 **한 번에 안 끝나기 때문**이다 — 커서 미표시 → 합성 커서 →
아이콘 FOUC → `fonts.ready` → 트림 → 다크 토글 → GIF 품질. 매 단계가 "찍어서 확인"이다.

라이브 프리뷰는 싸기만 한 게 아니라 판단도 낫다. GIF는 내가 짜놓은 동선만 보여주지만, 실물은 사용자가
직접 클릭·hover·리사이즈·다크토글 해본다. 그리고 위 실패 모드가 **아예 존재하지 않는다**.

## 입력 파악 (먼저 확정할 것)

| 항목 | 무엇 | 기본값 |
|------|------|--------|
| **대상** | gh issue 번호 또는 기능 설명 | (필수) |
| **시안 수 N** | 만들 후보 개수 | 3 (단순 개선이면 1) |
| **참고** | 스타일·이전 시안 게시 방식 참고 issue | 없음 |
| **범위** | 어느 컴포넌트/섹션을 건드리는가 | 이슈에서 추출 |
| **프리뷰 전달 경로** | 로컬 dev / 정적+로컬 서빙 / 별도 public 레포 Pages | 사용자에게 묻는다 (§4) |

N=1이면 "비교/선택" 단계를 건너뛰고 바로 구현→프리뷰 확인→컨펌→PR로 간다.

## 0. 세션 경계 (S1 → S2 → S3)

이 워크플로우는 **세션 3개로 나눠 돈다.** 각 경계에서 이어받을 내용을 파일로 떨구고 `/clear`를 안내한 뒤 턴을 끝낸다.
`/clear`는 컨텍스트만 리셋하므로 터미널·워크트리·dev 서버·MCP 연결은 살아 있다 — 새 터미널을 열 필요 없다.

| 세션 | 하는 일 | 끝낼 때 남길 것 |
|------|---------|-----------------|
| **S1** | §1 스코프 — 이슈·프런트 규약·현재 컴포넌트 통독, 시안 N개의 차별점 확정 | 시안 스펙 파일 |
| **S2** | §2~§4 — 병렬 제작·합치기·프리뷰 배포, URL 전달 후 **선택 대기** | 스펙 파일에 선택지 URL·브랜치명 추가 |
| **S3** | §5~§7 — 선택본 완성·미세조정·PR | (끝) |

**스펙 파일**은 레포의 플랜 디렉터리(예: `docs/woobin_plan/plans/variants-<issue>.md`)에 쓴다. 담을 것:
대상 이슈 요약 / 맞춰야 할 디자인 언어(간격·pill·아이콘·색·정렬) / **손댈 파일 경로**(컴포넌트명 말고 경로) /
시안 A·B·C의 구조적 차별점 한 줄씩 / 고정 데모 픽스처 값 / 기각한 시안 방향과 사유 / 각 단계 완료 판정 명령.

**왜 파일인가**: S1이 읽은 컴포넌트 코드·이슈 원문은 S2에서 다시 필요하지 않다. 그런데 안 끊으면 S2·S3의 **모든**
요청이 그걸 cache read로 재청구한다. 94aff112는 후반 137요청을 평균 250k에서 돌렸다 — 60k였다면 ~$13이 남았다.

**경계를 안 넘어도 되는 경우**(이유 한 줄 밝히고 진행): N=1이라 S2가 두세 턴이면 끝난다 / 이미 `/clear` 직후라
컨텍스트가 얇다 / 사용자가 이어서 하라고 명시했다.

**S2→S3 경계는 공짜다.** 어차피 사용자가 시안을 만져보는 동안 세션이 비어 있다. 여기서 안 끊으면 §6 미세조정
루프가 250~310k 위에서 돌게 되고, 그 루프는 원래 반복이 많다.

## 1. 스코프 (S1)

- 대상 issue를 `gh issue view <N>`으로 읽고, 참고 issue가 있으면 같이 읽는다.
- 프런트 규약 문서 + 손댈 컴포넌트의 현재 코드를 읽어 **맞춰야 할 디자인 언어**를 파악한다.
- N개 시안이 **서로 어떻게 다를지** 한 줄씩 정한다(예: A=단일 패널 인라인 확장, B=패널+중앙 모달,
  C=패널이 넓어지는 마스터-디테일). **구조/상호작용이 다르지 않으면 비교가 무의미하다** — 색만 다른 N개는 실패다.
- 위 내용을 스펙 파일로 저장 → `/clear` 안내 → 턴 종료.

## 2. 병렬 제작 (S2, N≥2)

> **게이트 — 시안 파일에 첫 Edit/Write를 하기 전에 멈춘다.**
> §2에 진입하면 코드를 건드리기 **전에** 이 두 개를 먼저 실행한다: 시안별 Agent 스폰 → `git worktree list`로
> 시안 수만큼 새 worktree 확인. 둘 중 하나라도 안 했는데 시안 파일을 편집하려 하고 있다면 그 자리에서 중단하고
> 에이전트로 전환한다. "일단 하나만 빨리 고치고"가 이 게이트가 막으려는 바로 그 동작이다.
>
> 왜: 2026-08-03(94aff112) 이 규정을 건너뛴 메인 루프 opus가 시안 3개를 직렬 제작해 Edit 66 + Write 30 +
> Bash 120이 한 컨텍스트에 쌓였고, 41k→348k로 자라 274요청 중 cache read만 58.2M($29.1, 세션의 72%)이 나갔다.
> 같은 성격 작업을 sonnet 서브에이전트가 한 대조군은 태스크당 $1.70~2.71. **위임은 선택이 아니라 비용 구조 그 자체다.**

- 시안마다 에이전트 1개를 **동시에** 띄운다. 각 에이전트는 **자기 worktree/브랜치**에서 작업한다.
- 프롬프트 맨 앞에 경로 가드: "첫 명령으로 `git rev-parse --show-toplevel`·`git branch --show-current`를 실행해
  메인 저장소나 부모 worktree면 아무것도 고치지 말고 즉시 BLOCKED 보고" + "`git add`는 지정 파일만,
  `git add -A`·`git commit -a` 금지". 스펙 파일 경로를 넘겨 배경을 읽게 한다 — 메인이 요약해 전달하지 않는다.
- **파일명을 시안별로 네임스페이스 분리하라** (`ProfileMenuA.tsx` / `ProfileMenuB.tsx` / …). §3에서 합칠 때 충돌이 없다.
  공용 파일(라우터·`App.tsx`·데모 픽스처)은 **오케스트레이터가 합칠 때 한 번만** 수정한다.
- 각 에이전트에게 **동일한 데모 픽스처 고정값**을 박아 넘긴다. 실제 데이터의 최장값(가장 긴 이름·ID)을 포함해 폭 스트레스를 태운다.
- **목업 HTML 금지.** 실제 코드 경로로 렌더돼야 한다. 백엔드가 필요하면 데모 모드(`VITE_DEMO_MODE` 류)를 쓴다 —
  없으면 만든다(HTTP 목킹보다 싸고 재사용된다).
- 각 시안은 **`typecheck` / `lint` / `test` 통과**까지 책임진다. 픽셀 완성도는 요구하지 않되, 깨진 빌드는 비교 불가다.
- 에이전트 리포트는 **브랜치명 + 통과한 게이트 + 한 줄 요약**만 받는다. diff를 메인으로 끌어오지 않는다.

## 3. 한 브랜치로 합쳐 토글 프리뷰 만들기 (S2)

- 통합 브랜치를 만들고 각 시안 커밋을 cherry-pick(파일명이 분리돼 있으면 충돌 0).
- **`?variant=a|b|c` 쿼리로 갈리는 스위처**를 얹는다. 화면 위 작은 전환 컨트롤도 둔다 — 같은 상태에서 세 구조를
  번갈아 봐야 차이가 느껴진다.
- 공용 파일(데모 사용자·픽스처)은 여기서 한 번만 정리한다.
- **검증은 `screenshot-verifier`에 1회.** "세 시안이 각각 렌더되는지, 빈 화면·에러가 아닌지"만 판정받는다.
  **메인 루프에서 playwright를 직접 몰지 않는다** — `browser_navigate`/`evaluate`/`snapshot` 왕복은 이미지가 아니어도
  메인에 쌓이고, 무엇보다 **확인 루프 전체를 메인에 묶는다**(94aff112: 200~300k 구간에서 playwright 41회).

## 4. 프리뷰 배포 (경로는 사용자가 고른다, S2)

| 경로 | 언제 | 대가 |
|------|------|------|
| **로컬 dev 서버** | 사용자가 같은 머신에서 볼 때 (기본 권장) | 준비 0·노출 0·HMR로 수정 루프 최저가. 세션 종료 시 내려감 |
| **정적 빌드 + 로컬 서빙** | 프로덕션 번들 상태를 봐야 할 때 | 수정마다 재빌드 |
| **별도 public 레포 + Pages** | 폰·다른 PC에서 봐야 할 때 | 아래 노출 규율 필수 |

**private 레포는 Pages를 그대로 쓸 수 없다.** Free 플랜은 private Pages 자체가 불가하고, Pro/Team이어도
**사이트가 공개로 뜬다**(접근 제한 Pages는 Enterprise 전용). 그래서 앱 레포가 아니라 **빌드 산출물만 담는 별도
public 레포**를 쓴다.

**프로젝트마다 상시 프리뷰 레포를 하나 두고 매번 재사용한다 — 시안마다 새로 만들지 마라.**

| 프로젝트 | 상시 프리뷰 레포 | URL |
|---|---|---|
| Pholex | `woobin-the-creator/pholex-preview` | https://woobin-the-creator.github.io/pholex-preview/ |

새 시안을 올릴 때는 **루트를 통째로 덮어쓴다**(이전 시안은 역할이 끝난 것으로 본다). 이슈 번호를 레포 이름에
박지 마라 — 재사용하면서 이름과 내용이 어긋난다(선례: `pholex-preview-191`이 #198 프리뷰를 담고 있었다).
목록에 없는 프로젝트면 `<project>-preview`로 새로 만들고 **이 표에 한 줄 추가한다.**

Pages 경로를 쓸 때:
- **올라갈 파일 목록을 사용자에게 먼저 명시한다.** 공개는 되돌리기 어렵다(캐시·인덱싱). 레포가 이미 있어도 생략하지 마라.
- 픽스처에 실제 사번·이름·부서명·lot id·내부 URL이 없는지 확인한다. 사내 프로젝트라면 건너뛰지 마라.
- **레포는 지우지 않는다**(상시 재사용). 대신 선택이 끝나면 다음 시안이 루트를 덮어쓴다.
- 산출물을 `main` 루트에 올리고 `.nojekyll`을 넣는다. Pages 활성화는 최초 1회만
  `gh api -X POST repos/<owner>/<repo>/pages -f 'source[branch]=main' -f 'source[path]=/'`.
  첫 배포는 1~2분 걸린다 — `curl -sI <url>`로 200 확인 후 URL을 준다. 이후 재사용할 땐 push 즉시 반영된다.

시안별 링크(`...?variant=a` 등)와 **각 시안의 특징·트레이드오프 2줄**을 함께 준다.
스펙 파일에 URL·브랜치명을 추가하고 → **`/clear` 안내 → 턴 종료.** 선택을 기다리는 시간은 어차피 비어 있다.

## 5. 비교 issue 기록 (선택, S3)

프리뷰는 임시라 기록이 남지 않는다. 결정 근거를 남기려면 대상 issue에 **시안 설명·트레이드오프 표 + 프리뷰 URL**을
텍스트로 올린다(스크린샷이 필요하면 사용자가 드래그 첨부 — private 레포는 raw URL이 인라인 렌더되지 않는다).

## 6. 완성 (선택된 시안, S3)

- 고른 시안의 브랜치를 작업 브랜치로 삼고, **나머지 시안 worktree/브랜치와 스위처 코드를 제거**한다.
  토글 스위처가 프로덕션에 새어나가면 안 된다.
- **프로덕션 품질로 마감**: 디테일 정렬·반응형·접근성·기존 스타일 정합.
- **미세조정 루프도 위임한다.** 사용자 요청이 여러 건 쌓이면 **묶어서 에이전트 1개**에 넘기고, 메인은 사용자의
  요청 문구와 에이전트의 한 줄 결과만 들고 있는다. 시각 확인은 `screenshot-verifier`. dev 서버는 계속 띄워둬
  HMR로 사용자가 즉시 보게 하되, **편집 왕복이 메인에 쌓이지 않게** 한다 — 이 루프는 원래 반복이 많아서
  한 번의 왕복 비용보다 누적이 문제다.
- 큰 디자인 트레이드오프 결정이었다면 그 레포의 결정 로그(예: `history/decisions.html`)에 한 줄 추가.
- 별도 컨텍스트의 리뷰 패스를 권한다 — 같은 컨텍스트에서 자가승인 금지.

## 7. 최종 녹화 + PR (S3)

**여기서 처음으로 녹화한다** — 선택된 시안 1개만. `pr-demo-video`의 REFERENCE.md 템플릿을 따르되,
아래 함정은 **미리 반영해 첫 시도에 성공시킨다**(전부 2026-07-30에 3개 에이전트가 각자 재발견한 것들):

- **애니메이션 전환은 ≥400ms.** 10fps 캡처에서 320ms 전환은 한 프레임 점프로 찍힌다.
- **`document.fonts.ready`를 await한 뒤** 캡처 시작. 아이콘 폰트가 로드 전이면 ligature가 글자로 보인다.
- 그래도 앞부분 1~2초는 트림한다.
- headless Chromium은 커서를 안 찍는다 → **합성 커서 + 클릭 리플 주입**이 기본.
- mp4는 raw 링크로 인라인 재생되지 않는다 — PR에는 GIF를 쓴다.

- PR을 열고 원본 issue를 `Closes #N`으로 링크. private 레포면 GIF는 사용자 드래그 첨부(경로 + 코멘트 URL을 준다).
- **merge는 사용자의 명시적 지시가 있을 때만.** "PR까지 올려줘"는 merge 승인이 아니다.
- Pages를 썼다면 프리뷰 레포는 **그대로 둔다**(상시 재사용). 다음 시안이 루트를 덮어쓴다.

## 함정

- **세션을 안 끊는 것** — 비용이 컨텍스트 크기에 정비례하므로, 안 끊으면 위임을 잘 해도 후반부가 200k+에서 돈다.
- **"이것만 빨리" 하고 메인에서 시안 파일을 편집하는 것** — 실측된 최대 낭비(72%가 cache read로 나갔다).
- **메인 루프에서 브라우저를 직접 모는 것** — 이미지가 아니어도 확인 루프 전체를 메인에 묶는다.
- **비교 단계에 GIF를 찍는 것** — 이 스킬이 고친 첫 낭비(실측 58%). 애니메이션이 판단 근거여도 실물이 더 정확하다.
- **시안끼리 차이가 없으면 실패다.** 색만 다른 3개는 비교가 안 된다 — 구조/상호작용이 다르게.
- **목업 화면을 시안이라고 내놓지 말 것.** 실제 코드 경로로 렌더한다.
- **worktree를 안 나누면 파일이 서로 덮인다.** 게다가 `isolation: worktree` 스폰은 **조용히 실패한 전례가 있다**
  (2026-07-04: 3개 중 2개가 부모 worktree에서 작업). 반드시 스폰 직후 검증한다.
- **에이전트에게 공용 파일 수정을 맡기지 말 것.** 각자 `App.tsx`를 고치면 합칠 때 전부 충돌한다.
- **private 레포 Pages는 공개 사이트가 된다.** 앱 레포가 아니라 프로젝트별 상시 프리뷰 레포(§4 표)로 좁힌다.
- **merge를 임의로 하지 말 것.** 따로 묻는다.
- **`screenshot-verifier`는 브라우저를 공유한다.** 이동을 지시했다면 돌아온 뒤 위치를 재확인한다.
- 임시 스크립트(`__*.mjs`)는 끝나고 지운다. `git status`에 의도한 변경만 남긴다.
