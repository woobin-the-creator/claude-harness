# 디자인 판단 규율

## 0. 값을 어디서 가져오나

이 문서는 **원칙**을 갖고 있고 **값**은 갖고 있지 않다. 값이 필요하면 이 순서로 찾는다:

1. **레포 루트의 `DESIGN.md`** — 있으면 이게 최우선이다. 아래 모든 기본값을 덮어쓴다.
2. **이 문서의 내장 기본값** — `[기본]`으로 표시된 것. 저자의 판단이지 물리 법칙이 아니다.
3. **그 순간 코드베이스를 읽는다** — "이 레포의 버튼 어휘가 뭔가" 같은 건 미리 물을 필요가 없다.
   그 컴포넌트를 쓰려면 어차피 읽는다. 사전 스캔을 요구하며 멈추지 마라.

`DESIGN.md`가 없다고 작업을 멈추지 않는다. 없으면 2·3으로 진행하고, **기본값을 썼다는 사실만 밝힌다.**
`DESIGN.md`를 만들고 싶다면 `references/instance-guide.md`에 양식이 있다.

## 1. 톤

**모노 잉크 + 절제된 accent.** 색으로 위계를 만들지 말고 **굵기·여백·경계선**으로 만든다.

- `[기본]` accent는 **1~2개로 고정**한다(라이트 1개·다크 1개). 그 조합이 브랜드다 — 화면마다 새 계열을 들이지 마라.
- `[기본]` 깊이는 **1px 경계선이 1순위**, 그림자는 1단만 보조.
- `[기본]` 표면은 평평한 단색. 그라디언트는 **토큰으로 명시 정의한 것** 외에 쓰지 않는다.
- `[기본]` **라벨은 값만큼 읽히게 만든다.** KPI 카드 타이틀·컬럼 헤더는 값보다 살짝 크게·굵게, 대비는 값과 같은 등급으로 — 위계는 여기서도 톤이 아니라 굵기로 낸다. (목업에서 라벨이 값과 톤이 비슷해 한눈에 구분되지 않았다.)

**pill 판정 휴리스틱**: "이게 **상태**를 나타내는 배지인가?" → 아니면 `9999px` 쓰지 마라.
개수·수량 태그는 상태 pill과 **구분되어야** 한다(선례: 그래서 일부러 3px 사각으로 둔 프로젝트가 있다).

## 2. 치수·비례 — AI slop이 가장 잘 드러나는 곳

색·그림자·모서리를 다 맞춰도 **치수가 틀리면** 여전히 AI가 만든 티가 난다. 기본값이 늘 "컨테이너를 꽉 채우고, 전부 같은 크기로, 중앙에 놓는" 쪽으로 수렴하기 때문이다.

**대원칙: 요소의 크기는 그 안에 들어갈 내용에서 나온다. 컨테이너 폭에서 나오지 않는다.**

| ❌ AI slop | ✅ 대신 | 실제로 이렇게 났다 |
|---|---|---|
| **입력칸 폭이 값 길이와 무관하게 균일** | 들어갈 값의 평균 길이에 맞춘다. `width: Nch` 또는 `size`로 값 기준 폭, `max-width`로 상한 | 폼에 `min-width` 하나만 걸고 입력 폭을 안 줘서 브라우저 기본 20자 폭이 됐다 — 3자 이름 칸이 9자 계정 칸과 똑같이 넓었다 |
| 폼 필드를 세로로 쌓고 각 칸을 컨테이너 폭까지 늘림 | 짧은 필드는 **한 줄에 나란히**(`flex-wrap`). 폼 전체도 가장 긴 필드에 맞춰 상한 | |
| 테이블 컬럼 균등 분할(`table-layout: fixed` N등분) | `colgroup`으로 **내용 길이에 비례** 배분. 좁아지면 `fr` 비율 조정 | 6등분이라 한 열의 값이 잘리고 헤더가 2줄로 깨졌다 → `0.85fr 1.15fr` 로 재배분 |
| 버튼을 컨테이너 폭 100%로 | 버튼 폭 = **라벨 + 패딩**. 폼 제출은 `align-self: flex-end` | |
| 모달 폭을 내용과 무관하게 큰 고정값으로 | **콘텐츠에서 역산.** 영상이면 종횡비 × 뷰포트 높이도 상한에 넣어 세로가 먼저 넘치지 않게 | `max-width: min(1120px, 94vw, calc(72vh * 1.6 + 36px))` |
| 빈 상태 = 중앙정렬 + 큰 패딩 + "데이터가 없습니다" | **왜 비었는지 + 다음 행동.** 목록 **안쪽** 빈 상태는 행 자리만 차지하게 작게 | 페이지 전체 빈 상태는 40px, 목록 안쪽은 12px로 갈렸다 |
| 로딩 = 화면 중앙 대문짝 스피너, 또는 안내 문구 한 줄 | **스켈레톤이 기본.** 실제 콘텐츠의 형상(행 수·칩 줄·셀 폭)을 그대로 잡아둔다 — 로딩 전후로 레이아웃이 점프하면 안 된다 | 행 수를 페이지 크기보다 적게 그려 데이터 도착 시 표가 늘어나며 튀었다. 칩 바 자리를 안 잡아 로딩 끝에 81px가 밀고 들어와 표가 내려앉았다. 셀 폭을 전부 같게 하면 데이터가 아니라 격자로 보인다 |
| KPI를 큰 카드로 부풀려 상단 절반 점유 | **한 줄 스트립.** 카드 테두리 없이 구분선·여백만으로 | |
| 모든 곳에 같은 gap·padding | `[기본]` **위계별로 다르게**: 셀 내부(4~6px) < 항목 간(8px) < 카드 내부(12~16px) < 카드 간(24px) | |
| 아이콘 + 제목 + 설명 3단 카드를 반복 | **데이터가 주인공.** 설명은 정말 필요한 곳에만, 아이콘은 식별에 기여할 때만 | |
| 남는 가로 폭을 요소를 늘려서 채움 | 폭이 남으면 **열을 늘리거나**(`auto-fill minmax()`) 그냥 비워둔다 | `margin-left:auto`가 이름과 작성자를 화면이 넓어질수록 계속 벌렸다 |
| 근거 없는 hover 확대·이동·트랜지션 | 상태 변화가 **의미 있을 때만**. 색·경계선 전환이 기본, 이동은 예외 | |
| **내재 높이를 가진 다중 섹션을 `flex:1; min-height:0` 컨테이너에 넣기** | 그 조합은 "컨테이너 하나 = 스크롤되는 자식 하나" 전제다. 자식이 여럿이고 각자 내재 높이를 가지면 컨테이너를 **내용 크기로 두고**(`flex:none`) 페이지가 스크롤하게 한다. `overflow`가 없는 컨테이너는 초과분을 **테두리 밖에 그린다** — 조용히 잘리지 않는다 | 카드가 495px인데 내용이 630px이라 자식이 테두리를 40.9px 관통하고 한 섹션은 카드 **바깥**에 통째로 렌더됐다. ⚠️ 카드 **하나**에만 `flex:none`을 걸면 형제가 남은 공간까지 줄어 이번엔 그쪽이 넘친다 — **형제 전부**에 건다 |

`[기본]` **radius 위계는 5단**: 인라인 태그 < 마이크로 버튼 < 항목·입력·소형 컨테이너 < 카드·패널 < 모달.
구체 px은 `DESIGN.md`에서 온다 — 없으면 이 레포가 이미 쓰는 값의 분포를 보고 정한다.

**치수는 실제 값으로 검증한다.** 더미 텍스트나 짧은 예시로 폭을 정하지 마라 — 실제 데이터(가장 긴 ID, 3글자 이름, 40자 사유)를 넣고 렌더해 잘림·과잉 여백을 확인한다. 위 컬럼 잘림·헤더 깨짐은 전부 실측에서만 보였다.

## 3. 정보 설계

1. **밀도 우선, 스크롤 최소.** `[기본]` 대시보드·모니터링 페이지는 단일 뷰포트(`height:100vh; overflow:hidden`, 구역 내부만 스크롤). 페이지 스크롤을 새로 만들지 마라.
   같은 원칙이 **컴포넌트 내부 스크롤에도 적용된다** — 새 스크롤 컨테이너(가로/세로)를 넣기 전에
   ① 이웃 요소를 옮겨 공간을 확보할 수 있는지, ② 접어서(overflow 팝오버 등) 상시 노출을 없앨 수 있는지부터 검토한다.
   스크롤은 "안전망"으로만 남기고 평소 경로에서 안 보이게 만드는 게 목표다.
2. **테이블은 한 화면에 행·열을 최대한 많이 넣는 게 1원칙이다.** `[기본]` 셀 텍스트는 `white-space: nowrap` + `text-overflow: ellipsis`로 **한 줄에 고정**한다 — 잘림은 `…`가 알리고 `title`이 확인해 준다(§4 hover 규칙과 같은 분업).
   두 줄이 필요해 보이면 컬럼 폭이나 값 포맷을 다시 볼 신호다(날짜 범위를 `08-11 › 08-12`로 줄이는 식). 한 셀이 접히면 그 행 전체가 두 배가 된다 — "시작 › 완료 예정"·"비고" 컬럼이 그렇게 표시 행 수를 깎았다.
3. **클릭 비용을 없앤다.** 탐색의 주 단서는 접어두지 않는다. ("100개를 훑으려면 100번 클릭"이 되는 토글은 지우고 상시 노출로 바꾼 선례가 있다.)
   같은 이유로 **다중 선택은 선택 결과가 접히면 안 된다.** 체크박스 드롭다운은 "지금 뭘 고른 상태인지"가 닫힌 목록 안에 숨어 매번 열어야 확인된다 — 선택 결과가 그 자체로 상시 보이는 형태(좌우 shuttle 등)를 쓴다.
   - **검색으로 좁힐 수 있는 다중 선택 목록에는 "결과 전체 선택"을 단다.** 검색이 100개를 10개로 줄여 줬는데 그 10개를 하나씩 눌러야 하면 "10개 찾기"가 곧 "10번 클릭"이라, 검색이 벌어 준 비용을 선택이 도로 까먹는다.
     대상은 **지금 보이는 결과**이고 라벨에 그 수를 적는다(`검색 결과 10개 전체 선택`) — 안 적으면 목록 전체를 고르는 건지 결과만 고르는 건지 눌러 봐야 안다. 토글로 만들어 되돌리기도 같은 자리에서 되게 한다.
     **검색이 없는 목록에는 달지 마라** — "결과"라는 개념이 없어 그냥 장식이 된다.
4. **화면에 DB 필드명을 노출하지 않는다.** `process_step = ETCH` ❌ → `공정스텝에 'ETCH' 포함` ✅.
   두 화면이 같은 개념을 보이면 **문구를 단일 출처로 공유**한다(공용 유틸 한 곳).
5. **라벨은 정직해야 한다.** 재는 게 로그인이면 "유저 사용"이 아니라 "유저 로그인". 데이터 없음과 값 0을 구분해 표시한다.
6. **넓어지면 열이 늘어난다.** `margin-left:auto`로 정보를 양 끝으로 찢지 마라 — 넓은 모니터에서 한 행의 정보가 분리돼 읽힌다.

## 4. 취향 기본값 — 시안이 갈릴 때

아래는 전부 `[기본]`이다. **저자가 실제 시안 비교 후 확정한 선택**이지 보편 진리가 아니다.
이 프로젝트에서 다르면 `DESIGN.md`의 "취향 오버라이드"에 **뒤집은 항목과 이유**를 적고 그쪽을 따른다.

- **관련 정보는 한 덩이로 묶는다.** 균등 분할해 여백에 흩뿌리지 않는다. (3분할 정중앙안이 "여백 속에 흩뿌려져 보인다"로 탈락한 적 있다.)
- **표준 위젯 > 창의적 위젯.** "직관적이지 않다"가 곧 탈락 사유다.
- **기존 문법 재사용이 새로움을 이긴다.** 새 상호작용 개념을 만들지 마라. (새 drill-down UI를 제치고 기존 테이블 문법 + 칩 필터가 채택된 적 있다.)
- **관습적 어포던스는 당연히 있어야 하는 것.** 필수 입력 빨간 `*`, 모달 바깥 클릭 닫힘, 로고 클릭 홈 이동.
- **어포던스는 쉬는 상태에서 드러나야 한다.** hover는 **확인** 수단이지 **발견** 수단이 아니다 — 마우스를 올려봐야 눌리는 줄 아는 컨트롤은 없는 것과 같다. 색으로 유혹하지 말고 **굵기·경계선·여백**으로 쉬는 상태에서 "이건 컨트롤"을 말한다(§1과 같은 수단).
  ⚠️ 캡션이 버튼이 되면 **색 대비도 같이 올려야** AA를 만족한다.
  - **같은 줄에 primary 버튼이 있으면 보조 액션을 무테로 두지 마라 — 어포던스는 절대값이 아니라 옆 것과의 대비로 읽힌다.** 모달 푸터의 "나중에 하기"·"취소"처럼 **거절·연기 액션**이 특히 위험하다. 눌러야 할 것 옆에서 톤을 낮추려다 "안 눌리는 것"이 되고, 그러면 남는 출구는 ESC·바깥 클릭뿐인데 그건 발견되지 않는다.
    **처방: 확정 버튼과 같은 버튼 어휘를 쓰고 primary 채움만 뺀다.** 톤 차이는 *채움 유무*로 충분하다 —
    **모달 전용 버튼 클래스를 새로 만들고 있다면 대개 이 실수의 전조다.**
  - **이 규칙은 산문으로 세 번 뚫렸다**(각각 다른 자리에서). 세 번째에 CSS 셀렉터 전수 스캔 테스트로 옮겨 CI에서 막게 됐다.
    쉬는 상태의 `border: 0` + `background: transparent` 조합이 판정 기준이고, 껍데기가 어포던스를 갖는 자리는 **사유와 함께** allowlist에 올린다 — 사유 없는 추가는 규칙을 지우는 것과 같다.
    ⚠️ **장식용 경계선 색을 컨트롤 어포던스에 그대로 쓰지 마라.** 장식 경계선은 WCAG 1.4.11 비텍스트 3:1을 못 넘는 경우가 흔하다 — **두께·radius만 빌리고 색은 텍스트 등급 토큰으로 새로 정한다.**
- **전환보다 누적.** 다른 대상을 볼 때 화면을 갈아끼우지 말고 **더해서 함께** 보게 한다. 비교가 목적인 화면에서 전환은 직전 상태를 지워 비교 자체를 없앤다.
- **첫 렌더도 완성된 화면이어야 한다.** 데이터 도착 전 화면이 "투박하다"는 건 미완성이 아니라 **완성도 결함**이다. 형상을 미리 세워두고(§2 로딩 행) 같은 상태를 가진 화면 **전부**에 일관되게 적용한다 — 한 패널만 스켈레톤이면 나머지가 더 도드라진다.
- **장식과 거짓 라벨을 싫어한다.** 기능하지 않는 UI는 지운다. 라벨이 실제와 어긋나면 **라벨을 지우는 대신 정직하게 만든다.** (`Live · {시각}`처럼 아무것도 안 재는 라벨을 실제 갱신 카운트다운으로 바꾼 선례가 있다.)
- **선택 목록이 20개를 넘을 수 있으면 검색을 기본으로 단다.** 그리고 검색 대상은 항목 이름뿐 아니라 **그 항목을 고르는 근거가 되는 값**까지다 — 부서를 고르는 사람은 부서명이 아니라 "그 사람이 어느 부서더라"에서 출발한다.
  이름이 아닌 값으로 걸렸으면 **매칭 사유를 화면에 적는다**(`○○○ 포함`). 안 적으면 검색어가 안 보이는 항목이 결과에 떠서 사용자는 검색이 고장났다고 읽는다.
  같은 목록을 두 화면에서 고르게 한다면 **검색 규칙도 같아야 한다** — 한쪽만 되면 어느 쪽이 고장인지 알 수 없다.
- **셀 수 없는 항목은 숨기지 말고 흐리게 두고, 이유를 글로 단다.** 있는데 안 보이면 사용자는 데이터가 틀렸다고 읽는다. 이유를 `title`(hover)에만 두는 것도 숨기는 것과 같다(위 어포던스 규칙과 같은 이유).
- **세로 공간 낭비를 낭비로 본다.** 콘텐츠에 안 쓰이는 높이는 줄인다.
- **모션은 GPU 경량 + 접근성 폴백 필수.**
- **브랜드 표현은 사람이 고른다.** 추천은 후보 제시까지.

## 5. 접근성 — 감이 아니라 실측

- **대비 AA 4.5:1**을 실제로 계산해 맞춘다. 라이트·다크 **양쪽** 최악값을 확인한다. 감으로 "충분해 보인다"라고 넘기지 마라 — 미달은 대개 3점대에서 난다.
- 비텍스트(테두리·아이콘·포커스 링)는 **WCAG 1.4.11의 3:1**이 별도 기준이다. 장식 경계선은 여기서 자주 탈락한다.
- 포커스는 모든 인터랙티브 요소에 **보이는** 아웃라인. 정렬 헤더에 `aria-sort`, 차트에는 스크린리더용 데이터 표.
- 모션은 `prefers-reduced-motion` 폴백을 함께 만든다.
- **테마가 둘이면 양쪽 다 확인한다.** 한쪽만 보고 통과시키면 다른 쪽이 깨진 채 나간다.

## 6. 작업 순서 (생성 → 정제)

1. **기본값부터 죽인다** — accent·radius·폰트를 의식적으로 고른다. "clean and modern" 기본값 = 엘리베이터 음악.
2. **한 컴포넌트씩** explore → critique → refine. 화면 전체 재생성 금지 — 매번 평균으로 회귀한다.
3. **개성은 빈틈에** — empty state·error·loading·microcopy가 craft와 AI 티가 갈리는 지점.
4. **옆에 놓고 본다** — 같은 화면의 기존 컴포넌트와 나란히 두고, 혼자 튀면 튀는 쪽을 고친다.

### 6-1. 자기 대조 — 코드를 쓰기 전에 한 번

체크리스트는 "☑ 했나?"를 자문자답하게 만들어 잘 작동하지 않는다. 대신 **관측 가능한 산출물**을 만든다.

계획을 세운 뒤, **같은 요구사항을 아무 규율 없이 받았다면 무엇을 만들었을지** 한 번 그려 보고 비교한다.
같은 곳에 도착했다면 그건 **선택이 아니라 기본값**이다. 고치고, **무엇을 왜 고쳤는지 한 줄로 적는다.**

적을 게 없으면 아직 아무 결정도 하지 않은 것이다.

## 7. 규율을 추가할 때

이 문서의 항목은 전부 **실제로 한 번 틀린 자리**에서 나왔다. 근거 없는 원칙은 다음 세션이 "이번 건 예외"라고 판단하고 넘긴다.

새 항목은 **세 칸을 다 채우되 각 칸을 한 절로 쓴다** — `틀린 형태` · `대신 이렇게` · `실제로 이렇게 났다`.
§2 표가 그 형식 그대로고, 목록 항목이면 한 줄 안에 세 칸을 담는다. 세 줄을 넘기면 `references/`로 내리거나 기계 가드로 옮길 때다.
선례는 남긴다 — 이 문서에서 코드를 읽어 알아낼 수 **없는** 건 그것뿐이고, 처방만 남은 규칙은 다음 세션이 예외로 판정한다.
처방은 **할 일로 쓴다** — "줄바꿈 금지"가 아니라 "한 줄에 고정한다". 금지형은 금지 대상을 오히려 불러온다.

같은 규칙이 **세 번째로 재발하면 산문을 더 쓰지 말고 기계 가드로 옮긴다**(§4 어포던스가 그 경로를 밟았다).
산문은 읽히지 않을 수 있지만 CI는 반드시 돈다.

프로젝트 고유의 값·선례는 이 문서가 아니라 그 레포의 `DESIGN.md`에 쌓는다.
