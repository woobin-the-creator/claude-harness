# Token Waste Audit

Claude Code 세션 로그(`~/.claude/projects/*/*.jsonl`)를 근거로 **낭비 습관을 진단**하는 스킬.
단순 비용 집계가 아니라 "어떤 발화·습관이 낭비를 유발했는지"를 실제 대화 발췌로 증명하고 해결책을 제시한다.

## 절차 (3단계)

번들 스크립트만으로 완결된다(외부 도구 불필요). 참고: ccusage·claude-token-analyzer 같은 외부 집계 도구가 세션에 이미 로드되어 있으면 총액 교차검증에 써도 되지만, 설치를 권하지는 말 것 — 2026-07 보안 검토에서 무고정 바이너리 자동 다운로드 구조 때문에 의도적으로 미채택했다.

### 1. 낭비 스캔

```bash
python3 {skill_dir}/scripts/waste_scan.py --out /tmp/token_waste_scan.json
```

- 옵션: `--days 30`(최근 N일만), `--projects-dir`(기본 `~/.claude/projects`)
- stdout 요약을 읽고, 카테고리별 수치가 이상하면(예: 총비용 0) JSONL 포맷 변화를 의심하고 샘플 레코드를 직접 확인한다.
- 가격표는 스크립트 상단 `PRICE` — 새 모델이 요약에 낯선 이름으로 나타나면 갱신 후 재실행.
- **결과 보관(전회 대비 재측정용)**: `mkdir -p ~/.claude/token-waste-audits && cp /tmp/token_waste_scan.json ~/.claude/token-waste-audits/$(date +%y%m%d)-days<N>.json`. 전회 파일은 이 디렉토리에서 찾는다 — 비교는 **같은 `--days` 범위**끼리만 유효하다.

### 2. 발췌 추출

```bash
python3 {skill_dir}/scripts/extract_excerpts.py --scan /tmp/token_waste_scan.json
```

카테고리별로 "낭비를 유발한 실제 발화"가 인용문으로 나온다. 보고서의 증거 컬럼 재료.

### 2.5 판단이 필요한 항목 보완

스크립트가 못 하는 세 가지는 직접 판단한다:

- **모델 과대/과소 선택(w2/w3 후보)**: scan JSON의 후보 목록에서 첫 발화·턴 수·출력량을 보고 실제로 부적합했는지 판별. 후보가 자동으로 낭비인 것은 아니다.
- **캐시 무효화 이벤트**: 같은 타임스탬프에 몰린 재캐싱은 병렬 요청의 정상 동작일 수 있다. 과대집계 가능성을 보고서에 명시.
- **설치된 자동화 감지**: `~/.claude/settings.json`의 hooks·설정에서 낭비 대응 장치(idle-handoff, rtk-rewrite 등)를 확인한다. 해당 카테고리는 전회 audit 수치와 비교해 효과를 재측정한다.

### 3. 보고서 작성

`references/checklist.md`(13항목 정의 + **해결책 사다리**)와 `references/report-template.md`(출력 구조)를 읽고 그대로 따른다. 핵심 규칙:

- 항목마다 **낭비액 + 실제 발췌(세션 ID 포함) + 해결책** 세 가지를 채운다. 발췌 없는 주장 금지.
- 해결책은 사다리 순서로 검토한다: **①기존 설정·플래그 → ②하네스 구현(훅·스킬·서브에이전트·statusline·cron 중 문제 유형에 맞는 수단) → ③습관 변경**. 습관 처방은 ①②가 불가능할 때만, 불가 사유 한 줄과 함께.
- ②단계 해결책은 처방문으로 끝내지 말고 보고서 끝 "지금 구현 가능한 개선" 섹션에서 즉시 구현을 제안한다.
- 낭비액은 휴리스틱 추정(±30%)임을 끝 인용블록에 명시.
- 구독제 사용자면 달러는 "API 환산 가치"임을 명시.
- 실측 0인 항목(예: 5분 TTL)도 표에 남긴다 — 걱정거리가 무해하다는 것도 결과다.

## 주의

- 세션 파일이 수백 MB일 수 있다. 스크립트 외의 방법(JSONL을 직접 Read 등)으로 전수를 읽지 말 것 — 그 자체가 이 스킬이 진단하는 낭비다. 발췌도 반드시 extract_excerpts.py 경유.
- assistant 레코드는 같은 requestId로 usage가 중복 기록된다. 토큰 합산 시 requestId 단위 dedupe가 필수(스크립트가 처리함). 직접 계산으로 우회하지 말 것.
- 보고서 발췌에 API 키·비밀번호로 보이는 문자열이 걸리면 마스킹하고, 사용자에게 해당 원본 세션에 민감정보가 남아있음을 알린다.
