# 토큰 낭비 체크리스트 (13항목)

보고서의 뼈대. 각 항목은 waste_scan.py JSON의 키와 대응한다.
항목별로 (a) 실측 낭비액, (b) 실제 대화 발췌, (c) 해결책을 채워 보고한다.

## 해결책 사다리 (하네스 우선, 습관은 최후)

해결책은 아래 순서로 검토한다. **습관 처방(3단계)은 1·2단계가 불가능할 때만** 낸다 — 습관 처방은 다음 audit에서 같은 항목이 그대로 재발하는 경향이 있다(2026-07 실측: "1시간 이상 비울 세션은 마무리하라" 처방이 2주간 15건 재발 → idle-handoff 훅 설치로 경로 자체를 종결).

1. **기존 설정·플래그로 해결**: settings.json(`autoCompactWindow`, `skillOverrides`, `skillListingBudgetFraction`, `model`, permissions deny/ask), CLI(`--idle-timeout`, `claude -p` 원샷). 이미 있는 스위치가 최선 — 유지보수 비용 0.
2. **하네스 구현**: 문제 유형에 따라 어울리는 수단이 다르다. 훅만 떠올리지 말고 전체 도구함에서 고른다.

   | 수단 | 어울리는 문제 유형 | 예 |
   |---|---|---|
   | 훅 (13종 이벤트) | 특정 시점에 개입이 필요할 때. 오탐 가능성이 있으면 반드시 소프트 개입(1회 경고 + 재시도 통과)까지만 | 유휴 감지 자동 핸드오프(Stop asyncRewake), 복귀 차단(UserPromptSubmit) |
   | 스킬/슬래시 커맨드 | 같은 작업이 여러 세션에서 반복될 때 — 올바른 절차(위임 등)를 절차 안에 고정 | 세션 검색 스킬이 Explore 위임을 내장 |
   | 커스텀 서브에이전트 (.claude/agents) | 대형 결과물(이미지·GIF·긴 로그)이 메인 컨텍스트에 남으면 안 될 때 | 스크린샷 검증 전용 에이전트 |
   | statusline | 차단은 과하고 상시 인지만 필요할 때 | 컨텍스트 크기 200k 초과 시 경고색 |
   | CLAUDE.md·메모리 규칙 | 모델의 판단이 필요해 스크립트로 판정 불가한 규율 | "주제 바뀌면 새 세션 제안" |
   | cron/schedule·백그라운드 에이전트 | 주기적 정리·점검 작업 | 주간 스킬/MCP 정리 리포트 |

3. **습관 변경**: 위 둘로 안 되는 것만. 처방문에 "왜 자동화가 불가한지" 한 줄을 반드시 붙인다.

**설치된 자동화 감지**: 보고서 작성 전 `~/.claude/settings.json`의 hooks·설정에서 낭비 대응 장치(idle-handoff, rtk-rewrite 등)를 확인하고, 해당 카테고리 수치를 전회 audit과 비교해 효과를 재측정한다(전회 기록이 없으면 이번 수치를 baseline으로 명시).

## 낭비액 산식 (근거)

- cache read = 0.1×input 단가, write 5m = 1.25×, write 1h = 2×
- TTL 만료 낭비 = 재캐싱 토큰 × input단가 × (2 − 0.1) / 1M  (캐시가 살아있었다면 0.1×로 읽었을 것)
- 200k 초과 유지비 = (컨텍스트 − 200k) × 0.1 × input단가 / 1M 를 요청별 합산
- 모두 휴리스틱 추정(±30%)임을 보고서에 명시할 것
