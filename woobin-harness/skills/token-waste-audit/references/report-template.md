# 토큰 낭비 Audit 보고서 — {기간}

## 결론 먼저

{기간}, {N}개 세션의 API 환산 총비용은 **약 ${총액}**이고, 이 중 **약 ${낭비액}({비율}%)이 회피 가능한 낭비**로 추정됩니다. 최대 낭비 요인 상위 3개:

1. {요인 1 한 줄}
2. {요인 2 한 줄}
3. {요인 3 한 줄}

## 주요 낭비 항목 (실측 순)

| # | 패턴 | 낭비액 | 실제 대화 발췌 | 해결책 |
|---|---|---|---|---|
| ... | (checklist.md 13항목 중 실측치가 있는 것부터, 낭비액 내림차순) | | (extract_excerpts.py 출력에서 인용, 세션ID 명기) | (checklist.md 기본 제안 + 사용자 환경에 맞춘 구체화) |

작성 규칙:
- 발췌는 따옴표로 원문 인용하고 세션 ID를 붙인다. 발췌가 없는 항목은 구조적 사실(예: 등록된 스킬 수)로 대체.
- 해결책은 checklist.md의 **해결책 사다리 순서(①기존 설정 → ②하네스 구현 → ③습관)**로 검토하고, 채택한 수단이 어느 단계인지 표기한다. 습관 처방(③)에는 "왜 자동화가 불가한지" 한 줄을 붙인다.
- 해결책은 "무엇을 하라"가 아니라 "언제 무엇을 하라"로 쓴다 (예: "1시간 이상 비울 세션은 떠나기 전 마무리").
- 실측 0인 항목도 표에 남기고 "해당 없음 — 조치 불요"로 표기한다 (사용자가 걱정한 항목이 무해함을 보여주는 것도 정보다).

## 설치된 자동화 효과 (전회 대비)

`~/.claude/settings.json`의 hooks·설정에서 낭비 대응 장치를 나열하고, 각 장치가 담당하는 카테고리 수치를 전회 audit과 비교한다. 전회 기록이 없으면 "이번이 baseline"이라고 명시한다.

| 장치 | 담당 카테고리 | 전회 | 이번 | 판정 |
|---|---|---|---|---|

## 모델별 비용 구조

| 모델 | 비용 | cache read | 출력 |
|---|---|---|---|

비용에서 cache read가 차지하는 비율을 한 문장으로 해석해준다.

## 최악 세션 사례 1~2개

세션 ID, 비용, 시작 발화, 무엇이 낭비를 키웠는지 서사로 2~3문장.

## 지금 구현 가능한 개선

②단계(하네스 구현) 해결책 중 이번 턴에 바로 만들 수 있는 것을 구체 설계(수단·훅 이벤트·소프트/하드 여부)와 함께 1~3개 제시하고, 구현 여부를 사용자에게 묻는다. 처방문만 남기고 끝내지 않는 것이 이 스킬의 기본 경로다.
